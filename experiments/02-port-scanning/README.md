# 🔬 Experiment 02 — TCP Port Scanning

## 📌 Objective

To identify TCP ports exposed by the Windows 11 target using Nmap and correlate the scan results with the TCP traffic captured in Wireshark.

The experiment focuses on understanding how TCP SYN probes and TCP responses relate to Nmap's `open`, `closed`, and `filtered` port states.

---

## 🖥️ Lab Setup

| Component          | Details         |
| ------------------ | --------------- |
| Attacker / Scanner | Kali Linux      |
| Kali IP            | `192.168.128.3` |
| Target             | Windows 11      |
| Windows IP         | `192.168.128.4` |
| Tools              | Nmap, Wireshark |

---

## 🛠️ Methodology

1. Start Wireshark and capture traffic on the lab network interface.
2. Run a default Nmap scan against the Windows 11 target.
3. Stop and save the packet capture.
4. Examine the TCP SYN probes generated by Nmap.
5. Correlate TCP responses with the Nmap results.
6. Compare the observed packet behaviour for open and filtered ports.

### Nmap Command

```bash
nmap 192.168.128.4
```

---

## 🔍 Results

Nmap identified the following open TCP ports:

|    Port | State | Service      |
| ------: | ----- | ------------ |
| 135/tcp | open  | msrpc        |
| 139/tcp | open  | netbios-ssn  |
| 445/tcp | open  | microsoft-ds |

The remaining **997 ports were reported as filtered with no response**.

Wireshark showed TCP SYN probes from Kali to the Windows target across the scanned ports.

The packet capture provides the underlying network evidence supporting the Nmap results.

---

## 📡 Packet Analysis

The observed TCP scanning behaviour can be summarized as:

```text
SYN
 ↓
Target response
 ↓
Nmap classification
```

For an open port, the target responds with a TCP `SYN, ACK`.

For ports where no response was observed, Nmap reported the ports as filtered.
